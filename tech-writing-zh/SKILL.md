# 中文内容生成（去 AI 味）

把内容改得像一个具体的人在讲一件他真做过的事。不追求"文笔好"，追求"有作者"。三个平台语体不同，但去 AI 味的标准一致。

## 核心立场

改稿前先记住三条，顺序不能反：

1. **语义优先**。技术事实、数字、边界声明（"不是生产级"这类诚实声明）一个都不许动。删的只是腔调，不是内容。
2. **减法优先**。大部分润色是删（删总结句、删排比、删元评论），不是替换词。一句已经自然、清楚、稳的话，不动它。过度编辑和改不到位一样糟。
3. **有作者**。读者检验一篇文有没有 AI 味，不是查禁词，是"能不能看出这是谁写的"。保留作者已有的口语词、节奏、立场。任何博主都能写的句子，重写或删。

## 执行顺序

1. **声音样本优先**。用户给过自己写的文字（博客旧文、历史笔记、上一版稿），先读样本：句长、用词、标点、开头习惯、刻意的小毛病。样本风格优先于本 skill 的通用规则——规则让位于真人声口。
2. **建信息账本**。改稿前登记全文事实：数字、专名、版本号、引语、限定词（"可能/仅测试环境"）、因果链。改完逐项回扫，账本里任何一项丢了、变了、从"可能"变"肯定"，都是事故。1500 字以上长文必做，短文心算即可。
3. 删 AI 痕迹：**先删段末收尾总结句**（"这说明/这展示了/到这里"开头的重述句），这是最高频的 AI 痕迹。
4. 顺句子：按目标平台语体顺（见 platforms.md）——博客和口语稿的"顺"标准不一样。
5. 调标点：减不必要的括号、引号、短句句号连发。
6. 全文回读一遍，只改卡顿点。B站稿要念出来改。

改稿前先过一遍 [references/patterns.md](references/patterns.md) 的**防误报清单**——改过头（把正常文章洗成大白话）和改不到位一样是事故，然后按模式库的病灶逐类处理。

## 需作者确认

原文本身逻辑超出证据支持（把"相关"说成"因果"、把"测试跑通"说成"可上线"）时，不静默替作者改正，也不放任。改写时保留原判断，在交付末尾列出：

```
【需作者确认】
- 第 3 段把"测试环境跑通"写成了"可上线"，我保留了原判断，你确认一下口径
```

## 硬规则

- **最小手术原则**。默认只动具体病灶句（对仗反射、升华句、引号抽象词），不换文体。作者的结构、枚举、"第一/第二"式叙述、平稳语体是体裁选择，全部保留。换文体（如书面转口语）只在用户明确要求时做。
- **不编造第一人称经历**。所有"我踩了坑/我卡了两天"必须来自用户提供的素材或他的 PROJECT_LOG。素材里没有，就留坑位：`[填：当时发生了什么]`，让作者自己补。宁可留洞，不许编故事。坑位集中列在文末还给作者，不大量内嵌打断阅读。
- **不主动加表演性口语词**。"太太太/居然/我去/哈哈"和"家人们/绝绝子/冲"是同一种表演。注意这不等于禁止口语：B站稿、小红书的目标语体就是口语，按 platforms.md 执行；禁的是无中生有的表演，不是口语本身。
- **素材门**。从零写长文前先盘点素材（真实数字、经历、引语、可验证来源）。每个计划中的小节说不出一个独有素材，就砍小节或写短点。目标字数不是注水的理由。
- **不发明平台事实**。不补写没发生的观众互动、播放数据、用户评价、产品能力；不编造导流链接和话题标签数据。
- **过时不改写**。文章落后于项目进度时，不把旧文改成新事实，在文首加更新横幅指向新文。

## 检测脚本

交付前跑一次，对命中处逐条判断（脚本报的是嫌疑，不是罪证；自然语境下的命中可以放过）：

```bash
python <skill-dir>/scripts/deslop_check.py <文件.md>
```

输出各类 AI 腔的命中数和行号。全零或仅有合理命中才算过。
