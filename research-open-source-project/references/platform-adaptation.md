# 平台适配工作流

仅当目标产物包含小红书、微信公众号、社交卡片、插图文章或 PDF 时读取本文件。

## 1. 选择执行模式

- `reviewed`：先创建并确认文章母稿、渠道策略和卡片脚本，再进行成本较高的生图或 PDF 导出。
- `one-pass`：当用户明确要求“一键生成”或“端到端完成”时，使用有证据依据的默认值执行完整流程，不重复询问常规风格偏好。将产物标记为待审核草稿，但不得跳过内部质量门。

面向中文专业技术分享的一键模式默认值：

- 人设：已经阅读 README 和源码的工程师同行；
- 语气：克制、重解释、敢于说明边界；
- 小红书：6 张 3:4 卡片，把最多空间留给两个核心机制页；
- 风格：没有品牌参考时，使用专业手绘知识笔记风格（`sketch-notes` 或 `notion`）；
- 不使用缺少证据的热度描述、紧迫感钩子、“一分钟看懂”或“建议收藏”；
- 微信公众号/博客：保留完整证据链、代码路径、竞品比较和资料来源；
- PDF：只从批准后的 Markdown 母稿生成，不把一组社交卡片直接拼成 PDF。

## 2. 定义渠道职责

创建 `channel-strategy.md`：

```markdown
# 渠道策略

- 执行模式：reviewed | one-pass
- 主要平台：
- 目标读者：
- 读者任务：
- 核心收获：
- 页数/字数预算：
- 本渠道必须讲完整：
- 留给长文展开：

## 图片与正文分工

- 图片负责解释：
- 发布正文补充：
- 发布正文不要重复：

## 默认语气

- 人设：
- 允许：
- 禁止：
```

把不同平台视为不同的阅读产品：

- 小红书要交付一个压缩但完整的认知模型，而不是文章碎片画廊。
- 微信公众号/博客要保留论证与证据链。
- PDF 要提供包含图片、图注和来源的连续阅读体验。

## 3. 建立逐页问题合同

在编写提示词或生图前创建 `card-script.md`：

```markdown
# 卡片脚本

| 页码 | 本页问题 | 核心结论 | 机制或示例 | 视觉关系 | Claim IDs | 精确文字 | 禁止添加 |
|---|---|---|---|---|---|---|---|
| 1 | 为什么值得研究？ | ... | 具体的多 Agent 场景 | 论点型封面 | C-002 | ... | Star、版本徽章 |
```

每张内容页必须包含：

1. 一个具体的读者问题；
2. 一个直接回答问题的结论；
3. 一条机制、因果链、示例或决策条件；
4. 一种明确的视觉关系，例如对比、流程、分层、时间线或决策树；
5. Claim ID 和必须准确的术语；
6. 禁止生成的事实性或装饰性内容。

如果删除解释后只剩几个名词，而页面含义几乎不变，则判定失败。词汇表不是技术讲解。

证据适配时，可以优先使用以下六页结构：

1. 中心论点和具体问题；
2. 与常见理解的核心区别；
3. 独特机制 A；
4. 独特机制 B；
5. 运行过程、代价或决策方式；
6. 竞品坐标、适用性和边界。

这只是默认结构，不是固定模板。把最多篇幅留给最能支撑独立论点的两个机制。

## 4. 让发布正文与卡片互补

创建 `social-copy.md`：

```markdown
# 发布文案

## 封面标题

## 发布标题

## 正文

## 仅在正文补充的证据与限制

## 标签
```

卡片负责认知模型、机制和比较；发布正文负责研究方法、来源依据、细节、限制和阅读路径。不要逐张复述卡片。

把热度、Star、发布状态、基准和竞品能力视为不稳定论断：浏览并给出来源，否则删除。不要让装饰性文字看起来像项目事实。

## 5. 交接给生图 Skill

仅在 `card-script.md` 通过内部审核后调用 `baoyu-xhs-images`，向它提供：

- 已批准的中心论点和渠道策略；
- 每页一个独立提示词文件；
- 卡片上的精确文字和 Claim ID；
- 禁止添加的文字、数字、版本、徽章和基准；
- 官方参考图或作者重绘来源；
- 目标尺寸和安全区；
- 必须在视觉上明显区分的角色。

使用第三方 Skill 负责渲染和系列一致性，不让它重新判断技术论点。

## 6. 把反馈转化为约束

保留旧版本，把反馈转换为明确约束后再生成：

```text
feedback.md → revision-plan.md → prompts-v2/ → images-v2/ → image-review-v2.md
```

每条反馈记录为：`原始反馈`、`失败类型`、`新增硬约束` 和 `受影响页面`。只有当首图锚点、视觉系统或跨页叙事发生变化时才重新生成整组，否则只重做受影响页面。
