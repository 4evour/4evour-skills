# 发布质量门

所有质量门通过前，不要宣布文章已经完成。

## 质量门 1：来源完整性

- 记录准确的分支/标签/提交和调研日期。
- 对会变化的事实进行浏览核验并给出来源。
- 官方截图和架构图可追溯到原始资源。
- 项目自报的基准明确标记为“项目自报”。
- README 材料被分类为 `reuse`、`adapt`、`verify` 或 `exclude`；复用的定义和资源保留来源说明。
- 不残留来源占位符、模板文字或无法访问的本地链接。

## 质量门 2：实现完整性

- 至少追踪一条端到端代码路径。
- 有源码时，至少两个论断引用具体代码路径。
- 不根据文件名推断运行时行为。
- 检查失败路径、异步边界和运维依赖。
- 引用的代码路径在被调研提交上仍然存在。

## 质量门 3：原创分析

- 一个中心论点出现在全文前三分之一。
- 即使论点建立在官方洞察上，也必须增加 README 之外的工程后果、因果解释、边界、比较或决策。
- 每个主要章节增加证据、综合、权衡、反方观点或可复用原则。
- 公平呈现最强反方观点。
- 准确定位创新发生在算法、数据模型、边界、工作流、治理还是产品封装。

## 质量门 4：竞品公平性

- 按核心抽象和成立条件比较竞品。
- 技术性竞品论断使用官方来源。
- 至少说明每个主要竞品一个更强的方面。
- 不用 Star 数或功能勾选榜单代替分析。

## 质量门 5：写作语气

- 像工程师同行交流，而不是厂商宣传或咨询报告。
- 事实、推断、观点和开放问题在语言上有清晰区别。
- 不使用空洞钩子、无证据夸张或重复的 AI 过渡句。
- 只扫标题也能看出论证路线。
- 列表中的项目确实并列；因果推理使用连贯正文承载。

## 质量门 6：视觉完整性

- 每张图映射到一个或多个 Claim ID。
- 官方资源标记为官方；分析图标记为作者分析。
- 图片不引入论断账本中不存在的事实。
- 生成文字清晰且准确。
- 没有生成卡片时，Markdown 母稿仍可独立理解。
- 只有在目标格式下可读时才直接复用官方图；重绘图记录来源。
- 可见的数字、版本、徽章和事实标签都有来源，否则删除。
- 当论点依赖不同角色时，视觉上明确区分角色。
- 每张讲解卡片都用机制、示例、因果链或决策条件回答一个问题。

## 质量门 7：交付完整性

- `article.md` 始终是可编辑的内容源头。
- 正文和视觉方案批准后才生图。
- Markdown 母稿批准后才导出 PDF。
- 相对图片路径可解析。
- 最终来源可阅读且有链接。
- 检查真实图片尺寸、安全区、顺序和文件数量。
- 原始生成图与格式统一后的发布图分开保存。

## 质量门 8：平台完整性（按需执行）

- `channel-strategy.md` 说明本平台必须讲清什么、哪些内容留给长文。
- 生成提示词前批准 `card-script.md`。
- 发布正文与卡片互补，而不是逐张转录。
- 一键模式只用默认值替代常规偏好确认，证据和质量门仍然必须执行。
- `image-review.md` 记录每张最终图片的事实、讲解、视觉和生产检查结果。
