# 研究质量门禁

研究包完成前，逐项确认以下门禁。脚本只能检查结构，不能代替人工判断事实。

## 来源完整性

- 记录了 exact branch/tag/commit 和研究日期；
- 易变事实有官方来源和访问日期；
- README 内容完成 reuse、adapt、verify、exclude 分类；
- 项目 benchmark 标记为 project-reported，未写成独立复现；
- 本地路径、占位符和不可访问链接已清理。

## 实现完整性

- 至少跟踪一条端到端代码路径；
- 有源码时至少两条重要事实绑定具体路径；
- 没有仅凭文件名推断运行行为；
- 检查了失败路径、异步边界、外部依赖和运营成本；
- 代码路径确实存在于研究 commit。

## 判断完整性

- 有一个独立于 README 的候选技术论点；
- 论点包含工程后果、因果解释、边界、比较或决策价值；
- 最强反论点被公平记录；
- 新意准确定位在算法、数据模型、系统边界、工作流、治理或包装之一；
- FACT、INFERENCE、OPINION、OPEN 用词清楚区分。

## 比较公平性

- 竞品按主抽象和系统层比较；
- 关键竞品事实来自官方仓库、文档、论文或 benchmark；
- 说明每个主要竞品在哪个条件下更强；
- 没有用 stars 或 checkbox 排行代替分析。

## 交接完整性

- `research-manifest.yaml` 标记了研究状态和 commit；
- `claim-ledger.md` 是下游文章的事实边界；
- `open-questions.md` 明确列出尚未证明的内容；
- 研究包没有夹带必须由文章或社交 skill 才能生成的产物。
