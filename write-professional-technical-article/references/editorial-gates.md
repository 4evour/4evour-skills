# 专业技术文章验收门禁

## 结构门禁

- `article-purpose.md` 明确读者、认知转变和非目标。
- 中心论点在文章前三分之一出现。
- 每一章都承担明确论证任务，删除后能说明损失什么。
- 章节顺序由论点和读者任务决定，而不是 README 顺序。

## 证据门禁

- 关键事实能回到 `claim-ledger.md`。
- 有源码时至少两条重要判断绑定具体路径、符号或测试。
- 项目声称、作者推断、作者意见和开放问题有语言区分。
- benchmark、版本、成熟度和竞品能力没有被写成未经核实的绝对事实。
- 最强反论点和失效条件被公平呈现。

## 解释门禁

- 每个关键机制都回答“发生了什么、为什么这样做、收益是什么、成本或边界是什么”。
- 不用名词列表代替因果链、示例或决策条件。
- 代码摘录服务于论点，而不是装饰。
- 删除图片后，文章仍能完成主要论证。

## 语言门禁

- 标题单独扫描时能表达文章推进的判断。
- 没有空洞开场、重复总结和模板化 AI 过渡句。
- 术语首次出现时有简短解释，全文用词一致。
- 事实、推断、意见和未知保持精确语气。

## 交接门禁

- `editorial-review.md` 记录结构和语言两轮审校结果。
- 文章未批准前不进入社交内容改写或图片生成。
- 视觉项使用 `visual-brief.md`，并绑定 claim ID 和准确来源。
