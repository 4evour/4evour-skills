# 底层概念图解讲解

把一个技术概念写成一篇读者能"自己推出来"的讲解。文章不是知识点的分类罗列，而是带读者从朴素模型出发，在模型解释不了的地方升级，最后搭出和真实机制对应的心智模型。

## 和另外两条线的分界

- 考点能拆成离散题目、答案有共识、读者任务是备面复习 → 八股线（bagu-explainer）。
- 主题有争议或在快速演化、读者任务是想选型或评估 → 研究长文线（research-open-source-project → write-professional-technical-article）。
- 主题稳定、机制有成体系原理、读者任务是从零学懂 → 本 skill。

同一个主题可以换线：线程调度讲给备面的人听是八股，讲给想学懂的人听是本文。

## 职责边界

本 skill 负责：

- 把概念系统还原成一条"朴素模型 → 失败观察 → 升级"的链；
- 设计贯穿全文的承重类比，并标注类比失灵点；
- 组织讲解顺序、每章的读者疑问和常见误解攻击；
- 把抽象机制锚在可观察的具体物（命令输出、任务管理器、日志行）上；
- 设计每章的图解任务并交给视觉 skill；
- 进行结构编辑、事实核实和文风终检。

本 skill 不负责：

- 罗列面试问答（那是 bagu-explainer 的 Q/A/W 结构）；
- 调研开源项目源码、竞品对比和 benchmark 证据；
- 社交平台改写和图片生成；
- 编造没有来源的数字。记不准的量级不写，或标注"以官方文档为准"。

## 必须执行的流程

### 1. 画概念地图

创建 `concept-map.md`：

- 从一个朴素模型开始（假设只有一个工人 / 只有一层缓存 / 没有并发）；
- 列出这个模型解释不了的观察（为什么切换程序会卡 / 为什么相邻变量访问更快）；
- 每次升级解决哪些观察、又引出什么新问题，直到搭出目标概念；
- 每一步标注"读者此刻会问什么"。

升级链断不掉的概念不适合本文，改用八股线拆题。

### 2. 登记承重类比

创建 `analogy.md`：

- 全文只用一个主类比，禁止每章换一个；
- 写出类比对象和真实机制的对应关系表；
- 明确标注类比到哪里失灵，正文走到失灵点必须说"到这里类比不够用了，真实机制是……"。

### 3. 设计升级式大纲

创建 `outline.md`。每章标题写升级动作，不写名词分类：

- ✅ "一个工人忙不过来：并发问题的起点"
- ❌ "线程的基本概念与分类"

每章四件事：上一模型的失败观察 → 新机制怎么解决 → 数字或命令锚点 → 这一层最容易产生的误解。

### 4. 写作

创建 `explainer.md`：

- 80% 的墨水花在反直觉处（切换的真实代价、伪共享、缓存行）；基础事实一句话带过，允许深度极不均匀；
- 每个抽象概念落到可观察的具体物：任务管理器里的数字、`lscpu` 的输出、日志的一行；
- 关键数字（缓存行 64 字节、上下文切换微秒级）先自查确定性，不确定的联网核实，核实不到就删；
- 主动攻击常见误解："很多人以为切换只是换个任务，其实光是把寄存器搬进搬出就要……"。

### 5. 设计图解

创建 `visual-brief.md`。每个升级动作至少一图：

```text
visual_id:
reader_question:
upgrade_step: 对应 concept-map 的第几步
exact_text: 图上必须逐字准确的文字
handoff: guizang-social-card-skill（默认，含精确文字/结构图）
```

低文字量的关系图、流程图可交 `baoyu-xhs-images`。

### 6. 两轮编辑与文风终检

创建 `editorial-review.md`：结构编辑（升级链是否连贯、类比是否承重、误解是否击中）和语言编辑（术语一致、节奏、重复）。

语言编辑后运行文风终检，结构病灶清单和检测脚本用法见 [references/style-rules.md](references/style-rules.md)。

## 输出协议

```text
concept-map.md
analogy.md
outline.md
explainer.md
visual-brief.md
editorial-review.md
```

下游社交内容 skill 只读取通过终检的 `explainer.md`。

## 写作规则

- 先给这章要解释的观察，再给机制；不要先下定义再举例。
- 读者记住的是转折（旧模型哪里不行），不是分类表。每章必须有至少一个"不行"的时刻。
- 讲解者可以有态度："这个设计其实挺激进""这是最容易误解的一步"。转述者判断不等于编造事实。
- 术语首次出现给英文原文（如"上下文切换（context switch）"），后文统一用中文。
- 允许一句话带过简单内容；每章等长等深是结构指纹，见 style-rules.md。
