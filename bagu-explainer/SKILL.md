# 八股知识讲解生成

把一个技术主题写成一套八股复习文档：按模块组织，每模块先"知识点"后"面试问答"，
读者先学后测。质量三支柱：讲因果不报名词、关键数字核实、格式绝对稳定。

## 核心原则

1. **讲因果，不报名词**。每个论点必须回答"为什么这样设计/不这样会怎样"，
   只写"Redis 使用了 IO 多路复用所以快"这类无展开句子的段落视为不合格。
2. **事实核实，讲解原创**。关键数字、版本、默认参数先自查确定性，不确定的
   联网核实（官方文档、权威资料站）。核实的是事实，讲解语言必须自己组织，
   禁止整段搬运任何资料原文。
3. **宁少勿错，宁短勿水**。给不出可靠数字就删掉这条，不编造；也不为凑
   篇幅注水——篇幅是考点数量决定的结果，不是预设的目标。
4. **格式稳定压倒一切**。问答每题三段（Q/A/W）齐全，没有可选段落；写不出
   W 说明理解不到位，回炉重写。

## 工作流

1. **列题单**：先凭面试频率自主列单，再用
   [references/topic-checklists.md](references/topic-checklists.md) 查漏——
   清单是防漏的参考快照，不是标准答案：清单外的高频模块（面经可证）照加，
   清单内与定位不符的模块（参考档位标注）照砍；主题不在清单内时，联网检索
   该主题高频面经与题库，自建同粒度清单。题单含场景设计题和排查题。
   **列单后先估篇幅**（见 output-format.md"篇幅规则"）：模块数和题量由
   考点数量自然决定，预估超过单篇 18 页上限就提前规划拆篇或按价值取舍，
   不做"先写完再删"。
2. **逐题核实**：对关键数字/命令/版本自查，不确定的联网查证；对某道题
   "是否高频"有疑问，查主流题库（JavaGuide、小林coding、面渣逆袭）的收录
   情况定夺，不凭印象。
3. **按模块两层写**（完整格式规范见
   [references/output-format.md](references/output-format.md)）：
   - **知识点层**：`关键字：解释` 条目，精准书面语（不口语化），关键字是
     自解释的术语锚点，解释带数字/命令/默认值
   - **问答层**：Q（≤25 字高频问题）+ A（60~120 字可背诵口语稿）+
     W（80~150 字场景化讲透为什么）；追问独立成题排在主问后，允许适度
     引入知识点层没铺过的内容，但不能超纲
4. **过质量门**：交付前逐条检查，不合格回炉：
   - [ ] 核心必考模块全部覆盖，砍掉或清单缺项都注明理由；清单仅作查漏
     参考，不要求覆盖清单全部条目
   - [ ] 适合的主题含场景设计题与排查题（缓存、数据库类几乎必有），
     不只原理题
   - [ ] 知识点条目标签是自解释的内容名，禁止"一句话收口""高频追问：XXX"
     这类只有作者懂的修辞标签
   - [ ] A 照着念给面试官听不违和；W 用场景推演/反证，读完能用自己的话推出 A
   - [ ] 每个论点有机制解释或具体数字，无"只报名词"段落
   - [ ] 关键数字/命令/版本已核实
   - [ ] 无 AI 味词汇和结构级 AI 味（禁词表 + 结构病灶清单见
     [references/style-rules.md](references/style-rules.md)）
   - [ ] 已运行 deslop_check.py 终检（或按结构病灶清单人工过检），
     命中逐条核对，自然语境的可放过
   - [ ] 输出严格符合 output-format.md 的 Markdown 模板
   - [ ] 单篇导出 PDF ≤ 18 页（平台硬上限，超了拆上下篇）；篇幅与考点
     数量匹配，无凑页注水
   - [ ] 无悬空引用：删改后检查知识点与问答互引的对象仍然存在
   - [ ] 文档自述的数字（页数/模块数/题数）与实际一致

## 输出格式

交付为 .md 文件，固定结构：H1 标题 + aside 引言 + 逐模块（知识点 / 面试问答
两层，模块间 `---` 分隔，从"一、"编号）。完整模板、条目写法与正反例见
[references/output-format.md](references/output-format.md)；
文风禁词与数字规范见 [references/style-rules.md](references/style-rules.md)。
