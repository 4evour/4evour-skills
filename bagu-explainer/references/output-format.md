# 输出格式规范（Markdown 模板）

交付物是一个 .md 文件，结构如下（模块间用 `---` 分隔，模块从"一、"编号）：

````markdown
# 后端八股总结 · {主题} 篇

<aside>

{三行内使用说明：这是什么、怎么用——先看知识点，再用问答自测。}

</aside>

## 一、{模块名}（{热度标注，可选：大厂高频/手撕级别高频/真题出现率极高}）

### 知识点

- **{关键字}**：{一两句精准书面解释，带数字/命令/默认值}
- **{关键字}**：{解释}
    - {可选子项：解法/优缺点/子分类，缩进四空格}

### 面试问答

- **Q1：{≤25 字的问题}？**（{热度标注，可选：追问率极高/大厂高频/爱考}）

A：{可背诵口语稿，60~120 字}

W：{场景化讲透为什么，80~150 字}
- **Q2：{追问独立成题}？**

A：{……}

W：{……}

---

## 二、{下一模块}
````

## 知识点层规则

- 每条 = `**关键字**：解释`。关键字是术语锚点，复习时扫关键字回忆整条；
  解释是**精准书面语（不口语化）**，一到两句，尽量带数字/命令/默认值。
- 关键字必须是**自解释的内容名**（"防幻读的两条路""冷页污染"），
  禁止修辞标签（"一句话收口""高频追问：XXX"）——读者扫标签要知道这条讲什么。
- 英文标准术语可以出现在关键字位（MVCC、ReadView、change buffer——这些是
  面试要说的词），解释正文用中文，术语首次出现给中文名。
- 每模块通常 4~6 条（小模块 3 条也正常，考点数量决定）；允许两层嵌套
  （问题下的解法、分类下的子项），不超过两层。
- 模块内部循序渐进：概念 → 问题 → 方案 → 实现 → 对比/边界。

## 问答层规则（Q / A / W 三段，全部必选）

- **Q**：≤25 字，面试官原话口吻，一题只问一件事（复合问题拆两题）；
  热度用括号标注在题尾。
- **A**：可背诵的**口语稿**，60~120 字。第一句就是结论，后面用"因为/另外/所以"
  自然连接；照着念给面试官听不违和。**不用①②③罗列、不用"标签词："格式**——
  那是把口语稿写成了提纲，背诵者还得自己重新组织发言。
- **W**：场景化讲透"为什么"，80~150 字。首选反证与场景推演（"想象两个事务先后
  改同一行""如果不这样做，会……"）；可用比喻但要准确；不重复 A 的内容，
  读者读完应能用自己的话推出 A。术语用中文表达。
- **每模块通常 1~2 题**：只有头牌模块给 2 题（如 MySQL 的事务与 MVCC、Redis 的
  持久化），其余模块 1 题；考点少的模块合并出题也可以。
- **追问**：独立成题（Q2）排在主问之后，形成主问 + 追问链的队列；
  允许引入知识点层没铺过的内容，但不得超纲；主问优先对应知识点层。

## 篇幅规则（内容决定篇幅）

- **唯一硬上限**：单篇导出 PDF ≤ 18 页——小红书单篇最多 18 张图。预估
  超限就提前规划：要么拆上下篇（每篇独立完整、互为钩子），要么按价值删减
- **篇幅是结果不是目标**：模块数、每模块条数由该主题的高频考点数量决定。
  MySQL/Redis 量级的主题通常落在 12~16 页；小主题（如单独成篇的 HTTPS、
  Cookie/Session）6~8 页完全正常；**禁止为凑篇幅注水**——稀释信息密度
  比短更糟
- **删减的价值标准**：删某条是因为"这个考点不值这个篇幅"（深 + 低频，
  追问链尽头的考点），不是因为"页数超了"。顺序：深+低频条目 →
  【加分】档模块（留作下篇钩子）→ 每模块题数（保主问砍追问）→
  W 层压缩（最后手段：W 是差异化价值，压薄了就退化成普通清单）
- **删减后必查断链**：被删条目若被其他条目或问答引用（如"冷页污染"引用
  "LRU 分代"的定义），要么补回一行定义，要么改写引用方

## 模块排序

按"循序渐进"排：是什么/为什么 → 怎么用 → 出什么问题 → 怎么排查治理 →
架构与生产。前一个模块是后一个的铺垫（不懂过期删除就看不懂内存淘汰）。

## 与旧格式的差异（勿回退）

- 不再使用"一题一页 + 四层结构（一句话答案/机制展开/追问链/加分点）"——
  那是围绕问答组织内容；本格式围绕知识点组织，问答只是模块的自测层。
- 每页 300~400 字、【第 N 页·题名】的旧分页格式已废弃。
